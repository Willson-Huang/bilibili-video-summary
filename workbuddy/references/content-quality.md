# 内容质量细则：广告过滤与专名校对

生成纪要时真正影响可检索性的两类问题：带货口播混进正文，以及专名被误识后仍是合法中文词、无人起疑。

## 一、广告过滤

视频里常有带货口播（拼多多、神奇小鹿、萌芽家这类），这些内容不得写入纪要。

两级处理：

1. **脚本预标记**：`bili_asr.py` 用 `ad_keywords.txt` 扫描转写段落，命中的段落在该行时间戳之后加 `[广告?]` 标记，并在素材包末尾生成「疑似广告段落」表格（时间戳 + 命中词 + 内容）。
   - 标记的准确形态是 `[hh:mm:ss] [广告?] 正文…`，它在行内、不在行首。按「行首以 `[广告?]` 开头」检索会得到 0 命中，进而误判「元信息说有标记、正文却没有」。核查时必须整行子串匹配，不要锚定行首。
   - 元信息行里标注的命中数含模板说明文字，不等于正文标记数。以「疑似广告段落表 + 行内标记」为准。
2. **AI 最终判断**：生成纪要时跳过所有带 `[广告?]` 的段落，不进核心结论、不进内容要点、不进金句。脚本只做提示，判断权在 AI——词表漏掉的广告口播同样要剔除。

词表可增删：直接改 `ad_keywords.txt`，每行一个词，`#` 开头为注释，改完立即生效。当前 74 词加 11 条排除短语。

### 撞车词与泛义词必须写限定形式

词表是子串匹配，写裸词必然误标。品牌名若与生活常用词、人名、书名或学科术语重合，只写全称或产品名——写「夸克」会误标物理科普、写「苏菲」会误标《苏菲的世界》，应为「夸克App」「苏菲卫生巾」。已清掉的裸词：

| 裸词 | 被误标的内容 | 改为 |
|---|---|---|
| `广告` | 招聘广告、广告登出 | `本期广告` / `广告合作` / `广告时间` |
| `工商` | 工商银行、工商业电价 | `工商合作` / `接工商` |
| `带货` | 直播带货（产业话题） | `带货链接` |
| `广告位` | 「千万元级的广告位」（讨论广告业态） | `广告位招租` |

同批清掉的裸词：`推广`（技术推广、推广普通话）、`赞助`（政府赞助）、`秒杀`（秒杀对手）、`甲方`（甲方乙方）。

「一拍即合」是真商单暗号、但也会误伤：雷军 P3 讲小米盒子与电视发布叙事时出现该词，被标 `[广告?]`。这类「信号真、但会撞」的词靠 AI 按上下文复核判断，不靠改表降低敏感度。

两个补救手段：

1. **限定短语**（首选）：加限定词（本期 / 合作 / 链接 / 招租）把撞车概率压到最低
2. **排除短语**：词表里以 `!` 开头的行，匹配前先从句子里剥掉。例：`!工商银行` 让「超越宇宙行工商银行成为A股第二高」不再命中；用于「已限定仍撞车」或「不值得为它牺牲敏感度」的词

**加词后的自检**：新增任何词都跑一次全库回放——把新词表套到 `cache/bili_subs/` 的素材包上，逐词看命中的样例是否都是真带货口播。撞车词会在样例里立刻现形，比事后修纪要便宜得多。

广告段落仍保留在素材包正文里（带标记），保证生成阶段可追溯；过滤只作用于纪要生成阶段。素材包不可用时（历史批次未归档），可追溯性由纪要「信息完整性」章节里的「广告段落处理」条目承担。

**纪实/产业类系列复核原则**：这类 UP主 正文大量提及品牌、产品、产业（拼多多、麦当劳、当地特产等），命中弱信号词属正常。生成纪要时必须逐段复核上下文——叙述城市产业、事件、特产属节目内容，保留并写入纪要；只有 UP主 本人的带货口播（念链接、优惠券、感谢金主、推荐购买）才剔除。实测某纪实系列 24 条全量处理，所有 `[广告?]` 标记段落经复核均正确区分，无大段误删。

## 二、专名误识

最危险的一类误识是**误识结果本身为合法中文词**：AI 读到时不会起疑，错误写法会一路带进正文、带进 frontmatter 的 entities，把正确名的检索入口堵死。典型例子：腾讯首席 AI 科学家「姚顺雨」被反复误识为「尧舜禹」（三个古代圣王，发音完全相同）。

`--hotwords` 只对 `funasr-nano` 生效，默认引擎 whisper 完全不吃热词，所以必须用事后校验加强约束兜底，三件缺一不可：

1. **术语表** `asr_glossary.txt`：机器可读的对照表，格式 `错误写法 | 正确写法 | 语境限定`。新增词条前先想：这个词会不会在正常语境下合法出现？会，就必须写语境限定（历史类内容里出现「尧舜禹」是本义，不能动）。
   配套的人工提示表 `专名误识速查-主题组.txt`（71 条，按广东 / 海南 / 制度政务 / 企业品牌 / 食物民俗 分组）。实测它只在同主题视频上有效，跨主题失效：拿它扫一份全新素材包命中 3 处、精度 0/3（「板」是电路板的本义；「旺达」确指向一处真错写，但正确名是「欣旺达」）。原因是条目多为特定视频的专名，换个视频就不出现，而常用词条目必然误报。正确做法是「按类型核查加常识」，速查表起注意力提示作用，不提供答案。
2. **派发子代理时把术语表相关条目抄进 prompt**：本批相关的人名、机构名、实测到的音近错写原样抄，不要凭记忆复述。
3. **校验脚本** `check_glossary.py`：每次生成完扫一遍 `raw/`。

   ```bash
   python scripts/check_glossary.py --dir <raw目录>                    # 只报告
   python scripts/check_glossary.py --dir <目录> --fix                 # 只替换 ALL 语境条目
   python scripts/check_glossary.py --dir <目录> --fix --force 词A,词B   # 点名替换需判语境的条目
   python scripts/check_glossary.py --dir <目录> --fix --force-all       # 全替换（含需判语境的）
   ```

   脚本会跳过「误识对照表」行（同行同时出现错误与正确写法视为订正记录，不是污染）；frontmatter 的 `entities` 同样会扫——那是检索入口，必须清。

   扫 `.workbuddy/` 下目录时：显式指定的扫描根不会被静默过滤（只过滤根之下新出现的 `scripts/` `references/` 等），命中数会打在 stderr 上。若命中为 0，先确认扫描根不是被过滤掉的。

## 三、校对三查（按类型逐类核查）

实测对照：速查表跨主题失效（扫一份全新素材包命中 3 处、精度 0/3），而按类型核查同一份素材包找出 3 处真错写。故校对以「按类型逐类核查」为主，词表只作注意力提示。三类必查：

1. **企业 / 品牌名**：抽含「公司 / 集团 / 企业 / 工厂 / 品牌 / 科技 / 电子 / 电池 / 地产」的行，逐个问「这家单位的真名是什么」。实测 `新旺达 → 欣旺达`（深圳动力电池公司）
2. **地名**：抽含「镇 / 区 / 县 / 村 / 街道 / 开发区」的行，核对与当地实际名称是否一致。实测 `重卡一带 → 仲恺一带`（惠州仲恺高新区，TCL 与德赛电池所在地）
3. **历史地名**：府 / 州 / 县治的旧称最容易错。实测 `阜城 / 抚沟 → 府城`（惠州府城）

为什么有效：ASR 把专名听错后，错写往往仍是合法中文词（重卡 / 阜城 / 新旺达），AI 与快速通读都不会起疑；只有主动问「这里提到的实体真名是什么」才会暴露。

**写作时遇到任何疑似专名，先查表再下笔**——把「怀疑」交给机器，把「确信」留给人。依据：曾一次性抓出 19 处同一专名的错误写法，连 frontmatter `entities` 都进了，检索入口被堵死。

## 四、误识诊断

`baseline_errors.py` 从 `raw/` 的人工「ASR 误识对照表」挖掘错误类型分布、分层纠错理论命中率与人工漏改率，用来回答「这批评分质量比上批好还是差」。只读，不写知识库、不改归档；依赖 `pypinyin`（缺失时自动降级为不做音系分类）。

```bash
python scripts/baseline_errors.py [--raw <raw目录>] [--out <报告.txt>] [--json <明细.json>]
```

当前基线：787 对样本 · 音系合计 55.4% · 人工漏改率 20.8%（非音系 29.2% 高于近音 20.6% 高于同音 13.3%）。判读：漏改率升高说明校对环节变松，重点盯「错写本身是合法中文词」那一类。
