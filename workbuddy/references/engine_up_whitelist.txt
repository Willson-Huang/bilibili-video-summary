# 引擎路由白名单：已验证的 UP 主 → 推荐引擎
#
# 格式：UP主名 | 引擎 | 依据 | 确认日期 | 依据类型
# 引擎取值：funasr-nano（中文专名密集）/ whisper（泛科技、英文术语多、快速初筛）
# 依据类型：实测验证（跑过并核对过专名）/ 标题归类（据 raw 标题推断，未经实测，首跑后应复核）
#
# 维护规则（自学习）：
#  1. 新 UP 主首次处理时，先用 `bili_asr.py <链接> --only-meta --classify` 拿关键词打分建议
#  2. 按建议跑完后，核对素材包里的专名是否正确（与官方字幕/常识对照）
#  3. 结论确认后追加一行到这里（写明依据与日期）——下次同 UP 主直接命中，不再猜
#  4. 判错的条目不要删，改判并加一行「修正」说明，保留可追溯性
#
# 注意：B站分区（tid/tname）对本场景不可靠（地理科普类视频实测被归到 tid 21「日常」），
#      不要拿分区当主要判据，只用 title/desc/UP主 三个信号。
#
# 下面两行是格式示例，用前请替换为你自己的记录：

<示例> 中文专名密集型 UP主 | funasr-nano | <系列/题材>；地名、人名、古迹名密集 | YYYY-MM-DD | 实测验证
<示例> 英文术语密集型 UP主 | whisper     | <系列/题材>；英文产品名与技术术语多，Nano 英文 token 易粘连 | YYYY-MM-DD | 标题归类
