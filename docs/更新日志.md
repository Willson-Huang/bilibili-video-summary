## v2.9.1 — 2026-10-13　[Release Notes](https://github.com/Willson-Huang/bilibili-video-summary/releases/tag/v2.9.1)

- **分P 视频全链路补齐**：多 P 视频每个 P 是一次独立转写、素材包按页分文件（`bili_<BV>_p<页>.md`），此前只有转写侧认这件事，收尾三个环节都按单份处理，于是分P 批次会卡住或误判
  - 归档：`library_queue.py --finish` 原来只认 `bili_<BV>.md`，分P 的 P1–P5 一份都搬不动，直接报「素材包归档失败」并拒绝置「已完成」。现在列出该视频的全部素材包逐个搬进归档目录，**每一份都过包体校验**，缺任意一份即整体失败（半套素材包等于丢掉误识修正的依据）；台账「素材包」列写第一份，其余追加在 `（分P 其余：…）` 里
  - 补发完成信号：对账脚本把该视频名下的各页素材包一并找齐，**每一页都配上纪要**才补发完成，只配上一页时跳过并说明还差哪一页；注册「待编译」按纪要文件名去重
  - 素材包校验：新增按包体头部声明的「分P：N/M」核对页号是否齐全，缺尾页也能查出——只按文件名清点时，目录里有的那几份看起来总是齐的（2026-10-03 实测：五分P 批次全部落空）
- **看板「面板闪一下就没了」四处修复**：浏览器进程未脱离父进程（服务一退出窗口被一起收走）、开窗线程是 daemon（主线程退出时夭折）、只探端口不校验进程（端口被别的进程占用时复用了一个不通的地址）、绑定失败抛在写记录之前导致重复开窗。修法见 `SKILL.md` 的对照表
- **事件解析移到锁内**：原先是「锁内查缓存 → 锁外读文件解析 → 锁内写回」，两个请求同时未命中会把同一批事件重复解析两遍；每个请求一个线程，轮询与首屏请求会并发触发它，任务量大时表现为 CPU 抖动、响应时间忽长忽短
- **批量转写不再丢卡片**：whisper 批量整段没有登记看板任务（此前只有 Nano 分支登记）；批量里每条都开新批次，导致跑完只剩最后一条。现在统一登记一次，批量调用只上报阶段
- **文档订正**：第十节由「待验证清单」改为「存疑标注」（只写一句注明归属，不排期、不进待办）；子代理约束澄清为「单个子代理只给一份素材包、素材包多时应并行派发」；`--limit` 的截断提示写明「不代表台账只有 N 条待处理」；「转写耗时」补上可从转写日志反解的结论（此前记为不可反解）；台账回写字段必须写成带类型键的对象，失败判据看返回体有没有 `error` 键
- 校验：三份副本自测全通过（Python 与前端）· 看板前端回归 **67 项** · 端到端验证 **70 项**

## v2.8.0 — 2026-10-02　[Release Notes](https://github.com/Willson-Huang/bilibili-video-summary/releases/tag/v2.8.0)

- **批次隔离：一个批次一个运行目录**（结构改动）。此前所有批次共用一个任务清单，新批次并入旧清单，于是已完成区越滚越长、批与批之间也无从区分。现在每次新的转写运行（批量或单条）会先把上一批整份归档到 `batches/<时间>-<来源>/`，再重建一个空的运行目录；转写脚本与看板两侧照旧读写同名目录，所以既有配置与调用方式都无需改动。看板顶部新增批次选择器，可切回任意历史批次（没有归档批时不显示）
- **未编译的任务看得见**：新增「待编译」阶段。转写侧与 wiki 编译侧本是两条任务，转写侧显示「已完成」只代表纪要写完。现在纪要写完时会自动登记一条「待编译」，看板不再把「只到纪要」显示成整批全部完成；不需要登记的批次可加开关关掉
- **收尾信号自动对账**：纪要写完后的「已完成」原先靠人工上报，实测漏了 7 次（3 次发到了别的名字下、4 次完全没发）。新增对账脚本，扫出看板里停在非终态的任务，只要标准纪要文件已经在目录里就自动补发；配不上则跳过并说明原因（素材包缺失、纪要不在目录、标点归一化后撞出两个候选），绝不编造完成。台账流程的收尾动作会自动调用它
- **「已耗时」改回任务实测耗时**：此前它算的是「当前时刻减运行目录建立时刻」，而目录不按批次隔离，于是显示成了目录年龄 —— 实测 415 小时（17 天），而任务实际耗时只有 3 小时多。现在改为各已完成任务的耗时合计，超过一天按「天 + 时 + 分」显示。同类修正：「预计剩余」只累加有依据的行，不再把人工阶段算成一个不存在的完成时刻
- **看板完成项收起并分区**：已完成任务只留「序号 + 标题 + 实际耗时」，悬停或键盘聚焦才展开其余信息；执行中与已完成分成两个区域。同一份数据实测列表总高由 3565px 降到 1894px
- **单条转写的任务名不再固定**：单条转写此前把任务名写成固定占位符，与登记时用的视频编号对不上，看板上表现为「有名字没有进度 + 有进度没有名字」两行。现在直接取音频文件名里的编号，两行合一
- 校验：看板前端回归 **67 项**、端到端 **70 项**、三份副本自测全通过；新增批次隔离一组 **21 条**断言
