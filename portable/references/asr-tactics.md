# 转写策略细节

引擎选定之后，真正决定输出质量的是这几个参数与处理路径。每条都是本机实测结论。

## 一、语言参数（两台引擎行为不同）

- **Nano 侧**：`--lang zh`（主脚本默认值）经 `nano_language()` 映射为 `auto`（自动检测）。不要强制「中文」——实测英文歌被强制中文识别后会输出「汝是汝，那会儿敢来迷住阮」这类错字。
- **whisper 侧不做映射**：`--lang` 原样传给 `faster_whisper.model.transcribe()`，而 `--lang` 默认值是 `zh`，不显式改参就整片强制按中文解码；`--prompt` 默认「以下是普通话的中文内容…」还会作为 `initial_prompt` 再压一层中文先验。跑非中文或中外交错的音频必须显式 `--lang auto --prompt ""`，否则外语段被音译成汉字串——形态像真中文，比乱码更危险。
- **即便 `--lang auto` 也不够**：faster-whisper 只在首窗（约 30s）检测一次语种并贯穿全片，没有逐段切换。中外交错的长音频单跑一遍拿不到正确结果。

## 二、多语种混合音频

适用对象：全球采访类 UP主，中文旁白与日语/西语/泰语/俄语受访段交替，时长常 2h 以上。

先按顺序把三个前置换算清楚，都不需要跑 ASR，全是接口层核查：

| # | 要查的事 | 怎么查 | 判据 |
|---|---|---|---|
| 1 | 有无字幕轨（能直取就不用 ASR） | `player/wbi/v2` 取 `subtitle.subtitles` | 返回 `[]` 即无字幕轨。必须做对照：同 UP主/同季其他集若返回 `ai-zh`/`ai-en`，说明接口与登录态正常，`[]` 是真无字幕 |
| 2 | 充电专属是否屏蔽字幕 | 对照同季另一集也是充电专属的视频 | 那集有字幕即排除「付费墙屏蔽字幕」这一解释（实测同季充电专属 Reaction 集有 ai-zh/ai-en/ai-ja，正片仍为 `[]`，是 UP主 未开字幕） |
| 3 | 音轨能否取到 | `player/wbi/playurl` 看 `dash.duration` 是否等于视频总长；再对 `dash.audio[].baseUrl` 发 `Range: bytes=0-2047` | `code:0` 且 `dash.duration` 等于 view 接口 `duration` 且 HTTP 206 且 `Content-Range` 总长合理，即完整音轨可取 |

**字幕有无跟时长强相关，与充电专属无关**（2026-09-19 同 UP主 两片复核）：

| 观测 | 数据 |
|---|---|
| 短片（20 分钟以内） | 普遍带 6 条 AI 字幕轨：`ai-zh` / `ai-en` / `ai-ja` / `ai-es` / `ai-ar` / `ai-pt`，B站 AI 字幕早已不止 `ai-zh` 一种 |
| 长片（50 分钟以上） | 一律 `[]`。实测 50 / 97 / 128 / 172 / 197 分钟五例全空，免费与充电专属皆然 |
| 反例排除 | 同一季里 20 分钟的充电专属特辑照样有 6 轨，既排除付费墙，也说明「充电专属即无字幕」不成立 |

遇到长片默认按「无字幕、必走 ASR」预估，不要因为同季短片有字幕就指望正片也有。

**内嵌硬字幕要单独查**（分P 名出现「双语版」时优先怀疑）：画面里烧了字幕不等于 B站有字幕轨。取 `x/player/videoshot`（精灵图，`img_x_len`×`img_y_len` 格、每格 480×270、`image` 是多张拼图），用 PyAV 解出 ndarray 后 numpy 裁切放大确认（本机无 ffmpeg / PIL，numpy + PyAV 够用）。实测某「双语版」正片确为画面内嵌中日双语硬字幕，且无任何字幕轨。

三个坑：

1. `videoshot` 的 `index` 时间戳与字幕时间轴有约 +5s 偏移。拿快照当基准跟 ai-zh 比对时必须先校正，否则会把 8/8 的吻合误判成错位。`index` 还可能返回空数组，重试 2–3 次即得，或按「视频时长 ÷ (图张数×100)」线性推算。
2. 默认 `--prompt` 曾被 whisper 吐成正文（已在脚本层修掉）：素材包首段出现 `[00:00:00] 请使用正确的中文标点符号。`。现由 `bili_asr.py` 的 `strip_prompt_leak()` 在转写后自动剥离（只清开头段、按 prompt 分句反复剥），结果 JSON 的 `asr.prompt_leak` 记录剥离段数，大于 0 即说明确有泄漏。跑非中文或中外交错音频仍要显式 `--lang auto --prompt ""`，那是为了关掉中文先验，与泄漏无关。
3. 画面内嵌字幕只能作语义级基准：UP主 会精简改写（实测「中国人拍我们拍不好之类」对应语音「中国人拍我们食堂不好之类的」）。不能当逐字 CER 基准，判定标准写成「关键串是否出现」。

三条可选处理路径，按成本从低到高，先跑抽样再定全片：

1. **抽样试跑定策**（推荐第一步，约 3 分钟）：挑 3 段各 60–90s（中文旁白段 / 主力外语受访段 / 另一语种段），分别跑 `--force-asr` 看输出形态。不要凭语种列表直接选引擎。
2. **切片转写**：按 5–10 分钟切片，每片独立调用 whisper（`language` 逐片检测），片内语言基本单一，绕开「首窗检测贯穿全片」的缺陷。代价是需补切片与全局时间戳偏移补偿，16 片另有 16 次模型加载。
3. **只取中文主线**：`--lang zh` 跑全片，外语段按 `[原文疑似]` 标注或剔除，纪要里说明「外语受访段未转写」。快，但丢掉片子最有价值的部分，仅当用户明确只要能看个大概时用。

Nano 不要用在这类内容上：官方定位是中文专名强，外语不占优、英文 token 易粘连；2h09m 音频按实测 2.1x–5x 折算需 26–61 分钟，多语段质量更差。

## 三、热词规范

- 不是零成本开关：VAD 每个分段都会重新注入热词前缀，长视频切 35–60 段即热词被处理几十次，不是一次性
- 默认 20–50 词，硬上限 80（超长会注意力稀释、误插词）
- 来源：标题、简介、UP主名、已知人物/地名/机构、频道专属词表；去重并按相关性排序
- 文件不存在不阻断转写，但元数据标 `hotwords_status: missing`，stderr 会警告。提交了热词文件却看到该状态时，先修正路径再采信专名结果。重复项与 `#` 注释行自动过滤
- 状态四态：`loaded` / `empty`（文件在但无有效词）/ `missing`（路径不存在）/ `disabled`（未传）
- 空转写保护：Nano 返回 `timestamp_status`，`ok` 才入库；`no_ts`（有正文但解析不出时间戳）与 `empty`（静音或无内容）一律判失败，不生成空素材包。知识库依赖 `[hh:mm:ss]` 引用，无时间戳的素材包不许进流程
- 元数据记录有效词表的 `hotwords_sha256`、源文件的 `hotwords_source_sha256`、数量、截断与状态，供追溯「某个专名为何被这样识别」
- 热词只对 `funasr-nano` 生效，whisper 完全不吃热词

## 四、批量语义

- 结果严格按输入 items 顺序返回；中间项失败也留在原位，不会串位（上游队列按序 `zip` 回填台账，乱序会把 A 的状态写到 B 上）
- `model_load_sec` 只记在首条（批级开销），`asr_sec` 是逐条实际 generate 用时，台账「转写耗时(秒)」不会把整批总耗时重复记到每条
- 批量结束按 `--keep-audio` 清理原始音频；adapter 内部转码的 16k WAV 用完即删；Cookie 用一次性临时文件并在 `finally` 删除
- `--batch-file` + Nano 时，脚本先下载全部音频再一次加载模型处理整批（`funasr_adapter.py --batch-json`），避免每条重复 48–52s 冷启动。单条 Nano 调用仍是每条一次冷启动，只适合单发

## 五、架构约束与输出归一

Nano 跑在独立 venv（`~/.workbuddy/binaries/python/envs/asr_eval`），funasr 依赖与 faster-whisper / CTranslate2 冲突，绝不合并装。主脚本经 `funasr_adapter.py` 子进程调用，输出归一为 `[{start, end, text}]` 写入同一套素材包格式，接入与回退都不影响 14 节纪要流程。

Nano 不返回句子级结构（`sentence_info` 为 None），adapter 从 token 级 `timestamps`（单位秒，对应 LLM 正确分支；不要用 `ctc_text`，那是较弱的 CTC 分支，错误模式与 whisper 同款）按标点与间隔聚合成段落，并清理孤立标点段，保证素材包正文是 `[hh:mm:ss]` 可读段落。

## 六、已知限制

- 英文/音乐内容走 whisper：Nano 的英文 token 拼接偶发粘连（如 `strangerstolove`），中文场景无此问题
- 事件标签已过滤：`[noise]`、`[SP K]`、`[BGM]` 等纯标签段不进素材包正文
- 依赖装法：funasr 的 `numpy<2` 约束在 Python 3.13 下已过时，必须 `pip install --no-deps funasr` 加手动安装 numpy 2.x，不要把 funasr 装进 whisper venv
- Nano 侧调参（`batch_size`、VAD 段长、砍热词、双进程）全部零收益，见 `perf-benchmark-2026-09-13.md`

## 七、有 AI 字幕时的双源做法

内容泛科技、英文产品名密集时默认字幕直取即可；若产品名、型号、人名需要可追溯（评测、发布会解读、企业史），走双源：

```bash
# 1) 字幕直取跑一遍，主包是字幕版
bili_asr.py <链接> --out <.workbuddy/cache/bili/bili_<BV>.md>
# 2) 手工把字幕版另存为旁证（脚本不会自动留）
#    复制 bili_<BV>.md → bili_<BV>.subtitle-ai.md
# 3) 用本地 ASR 覆写主包，作为正文基准
bili_asr.py <链接> --force-asr --engine whisper --out <.workbuddy/cache/bili/bili_<BV>.md>
```

- 主包是本地转写（正文基准），`*.subtitle-ai.md` 是 AI 字幕（只作对照，不可作基准——它是另一路中文识别，专名同样会错，且与本地转写错点不同）
- 归档时两份一起挪进 `bili_subs/`，后续专名回查才有第二个来源
- 两源一致直接采信；不一致且常识判不了，正文用主源写法，同时进「ASR 误识对照表」并在第十节标 ⚠️ 注明「两源写法不一致」，不猜、不做含糊化改写
- 实测收益：某 AI 手机评测片双源对照出 4 处不一致，其中 2 处可判定（型号统一、术语经片内互证），2 处留待核实
